## 5. Virtual Container Dataset Generation (End-to-End)

`DatasetGenerationService.generate()` measured across three workload sizes.
Includes: chunk allocation, subchunk creation, worker processing, SHA-256 integrity
check, and file persistence to disk.

### 1 MB Job

| Metric | Value |
|--------|-------|
| Generated bytes | 1,048,576 |
| Total elapsed | **0.051 – 0.066 s** |
| Generation rate | **41.8 – 51.5 MB/s** |
| Persistence rate | **56 – 90 MB/s** |
| End-to-end rate | **15.2 – 19.5 MB/s** |

### 5 MB Job

| Metric | Value |
|--------|-------|
| Generated bytes | 5,242,880 |
| Total elapsed | **0.182 – 0.189 s** |
| Generation rate | **49.5 – 49.9 MB/s** |
| Persistence rate | **263 – 284 MB/s** |
| End-to-end rate | **26.5 – 27.5 MB/s** |

### 10 MB Job

| Metric | Value |
|--------|-------|
| Generated bytes | 10,485,760 |
| Total elapsed | **0.328 – 0.391 s** |
| Generation rate | **44 – 48.9 MB/s** |
| Persistence rate | **255 – 491 MB/s** |
| End-to-end rate | **25.6 – 30.5 MB/s** |

**End-to-end rate** = `generated_bytes / total_elapsed_seconds`.  
**Generation rate** = throughput of the data-generation layer alone.  
**Persistence rate** = disk I/O rate of the output commit phase.

The limiting factor is CPU-bound data generation (~45–50 MB/s sustained).
Persistence is I/O-bound and scales significantly with workload size due to
OS page-cache warm-up effects.

## 6. Interpretation Notes

- **Router vs. cryptography**: The trie router is ~17,000x faster than Ed25519 signing.
  In production, cryptographic overhead dominates request latency for small bodies.
- **Dataset generation bottleneck**: Pure Python data generation saturates at ~50 MB/s.
  For higher rates, replace with NumPy-based or C-extension data generators.
- **AES-GCM speed**: 1,750+ MB/s means AES encryption adds <0.001 ms overhead for
  typical 10–100 KB request bodies — negligible relative to Ed25519 signing time.
- **Vercel cold starts**: The measured cold start of ~6 ms (in-process) is the module
  import time only. Vercel serverless cold starts include additional container
  spin-up time (typically 200–800 ms in practice).
